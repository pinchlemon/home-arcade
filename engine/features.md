# Features

A feature is a small add-on to a game: a mechanic, an effect or a rule. It lives in one file and comes with its own controls in the Studio, so the owner can switch it on and off and tune it by touch on her phone. Features are how mechanics get prototyped: Claude writes one, she plays it and tunes it, and then keeps it, changes it or switches it off.

Void Wizard is the first game with features: the Lab (on, see below), Sparkle trail (off) and Custom text (on; changes the title, score label, tip, mode link and the line under each solid). The Studio's Features tab shows them, and its **Ask Claude** button writes a request that she pastes into a Claude Code session.

## The three parts of a feature (example: `trail` in Void Wizard)

1. **The code**, in `<game>/features/<id>.js`:
   ```js
   feature('trail', ({ game, set, on }) => {
     on('frame', (dt) => { /* runs every frame */ });
   });
   ```
   - `game` is what the game hands over (below).
   - `set('rate', 40)` reads one of the feature's settings, and falls back to the number given if the setting is missing. Give words as the fallback (`set('title', 'VOID WIZARD')`) and it reads words instead.
   - `on(event, fn)` hooks into the game.
   - A feature that throws an error shows a red note in the corner, and the game keeps running.
2. **Its numbers**, in `game.json` under `features`:
   ```json
   "features": { "trail": { "on": 0, "rate": 40, "size": 0.5 } }
   ```
   `on` is 1 or 0. `engine/boot.js` loads `features/<id>.js` only when `on` is 1, so a feature that is off costs nothing and changes nothing.
3. **Its controls**, in `studio.json` under `features`:
   ```json
   "features": [{ "id": "trail", "name": "Sparkle trail", "about": "What it does, in one line",
     "fields": [{ "path": "features.trail.rate", "label": "Amount", "help": "Sparks a second", "min": 5, "max": 200, "step": 5 }] }]
   ```
   - The Studio adds the On switch (`features.<id>.on`) by itself.
   - Fields are the same as settings fields: `show: "seconds"` shows frames as seconds, `show: "percent"` shows a 0 to 1 number as a percent, and `show: "onoff"` makes a switch. `show: "text"` is for words: the row shows the words and a pencil to type new ones (`max` is the most letters, 300 if left out; `min` and `step` aren't needed).
   - Changes are kept on the phone and pushed onto `game.json` like any other setting.

Adding a feature means writing these three parts, adding the new file to `PRE` in `sw.js`, and bumping the version (see CLAUDE.md). Keep the feature's default numbers the same in `game.json` and in its `set()` calls.

## Void Wizard: what `game` has

- **Things:** `THREE`, `scene`, `camera`, `player` and `buddy` (the blue and red wizards), `you` and `mate` (whoever you control now, and the other one: the Lab's Party shelf can move control between wizards), `ALL` (the wizards), `orb` (the Solid), `orbMesh` (the group that draws it), `demon`, `demonParts()` (the demon as spheres `{x, y, z, r}`), and `SOLIDS`.
  - `solid` is the current solid. Its `col` is the colour, and it also has `grav`, `hang`, `speed` and the rest. `setSolid(S)` turns it into one of `SOLIDS`.
- **Time and input:** `time`, `keys` (a Set of the `KeyboardEvent.code` values held down), and `pad` (player 1's raw Gamepad, or null). Set `blockPad = true` to take the controller away from the game (the Lab does while it is open). `padSkip` (a Set of button numbers, or null) hides just those buttons from the game; Lab shelves don't set it themselves but call `LAB.skip(owner, [buttons])` (null gives them back), which joins every shelf's list. A wizard's own controller is `W.gp` (fresh each frame). `DUEL` and `PARTY` say which mode is running.
- **A wizard** has `pos`, `vel`, `y`, `vy`, `yaw`, `grounded`, `downT` (more than 0 while knocked down), `charging`, `charge` and `root` (its three.js group).
- **Effects:**
  - `spark(at, vel, life, size, color, drag, gravity)`, `sparkBurst(at, n, speed, size, drag, color)`, and `spawnPuffs(n, speed, at, size)`.
  - `popup(text, at, cssColor)` and `shake(amount)`.
  - `fxRing(x, z, color, radius, seconds)`, `fxPillar(...)`, `fxSphere(...)`, `fxBurst(...)` and `rumble(wizard, strong, weak, ms)`.
- **Actions:** `motes` (the specks in the void, a `THREE.Points`), `swapTo(W)` (you take over that wizard; it fires a `swap` event), `stick` (the move input this frame, `{x, z}` on the ground), `changeHook` (a function Triangle calls first when you are empty-handed in the demon game; returning true stops the buddy-mode change), `makeWizard(robe, trim, glow)`, `joinCrew(W)` and `leaveCrew(W)` (more wizards in the demon game; the demon then goes for whoever is nearest), `brain` (set a function `(W, dt) => input` to drive the wizards you don't control; null keeps the buddy's own brain), `lobTo(W, charge, x, z, quick)`, `shootAt(W)`, `solidSpot(out)` (where the Solid will come down), `demonNearest(p)`, `demonAim(W)`, `LOB_MAX`, `CATCH_R`, `passTarget(W, dx, dz)` (the teammate a pass from W facing that way would go to, or null), `knockDown(W, dx, dz, power)`, `pushBack(W, dx, dz, power)` and `hurtDemon(at, damage, color)`, `hpBar` (the demon's health bar), `resScale` (set below 1 to draw fewer pixels; the Lab's Sharpness setting), `hudOff` (true skips drawing the corner badge while it's hidden), `headCenter(out)` (the demon's mouth), `venoms` (the spit gobs, `{g, v, alive, puddle, r}`; `r` scales a gob's hit size), `spitHook` (set a function `(W) => bool` the demon calls in place of spitting at W; true means it did its own attack), `bossHook` (set an object `{update(dt), spawn(), parts(), mouth(out)}` to put your own boss in place of the centipede: the game then calls `update` in place of the centipede's moves and `spawn` in place of its spawning, and asks `parts()` (spheres `{x, y, z, r, weak}`, the weak spot first, counted as the head) wherever it would use the centipede's body: `demonParts`, aiming, `demonNearest`, `demonAim` and the Solid's hits; `mouth(out)` stands in for `headCenter`. Health, `demonHit`, `killDemon` and `demonDown` stay the demon's own, so the hook handles `dying` (counting `dieT` itself), sets `alive` false and `spawnT` when its death is done, and `spawnT` counting down while it's gone; null puts the centipede back), `throwHook` (set a function `(W) => bool` that `playerThrow` calls first when a person throws; true means it threw), `playerThrow(W, shot)` (shot true: the hard, flat jump throw at the demon, from the ground too), `throwOrb(W, charge, dx, dz, across, up, exact)`, `padAlias` (a feature's `{slot: button}` map: the game's job for that button read from another), `G` (gravity; times `solid.grav` for the Solid's), `shakeHook` (set a function `(camera, shake, dt) => left` that moves the camera in place of the game's own shake and returns the shake left), `aimHook` (set a function `(W, ix, iz, il, dt) => yaw` that turns a winding-up wizard in place of facing the stick; `W.aimMove` scales walking while winding up), `orb.labMul` (extra damage for the throw in flight, read when it hits), `spawnDemon()` (a fresh demon now, where the game would put one) and `demonMax` (the demon's full health) (`at` is any `{x, y, z}`, such as one of `demonParts()`).
- **Screen:** set `post` to `{ target(renderer), draw(renderer) }` and the finished picture (world and solid, not the HUD) is drawn into `target`'s render target, then `draw` puts it on the screen. `null` (normal) draws straight to the screen. The Look shelf uses it.
- **Multipliers:** `MOD` holds `speed`, `jump`, `gravity`, `time`, `demon` (the demon's full size), `knock` (0: nobody gets knocked down) and `hp` (the demon's health), all 1 normally, and `turn` (0 normally: turns your controls, in radians, to follow a turned camera). For example, `game.MOD.time = 0.5` is slow motion.
- **Events** (`on(name, fn)`):
  - `frame(dt)`, every frame after the world moves and before it is drawn.
  - `camera(camera, lookAt)`, after the game places the camera, so a feature can move or turn it.
  - `jump(W, inAir)`, `land(W)`, `throw(W, charge)`, `catch(W, caught)` (caught is false for a pick-up), `dive(W)`, `tackle(W)` and `knockdown(W)`.
  - `demonHit(damage)` and `demonDown()`.
  - `venomSplash(V)`: a spit gob hit the floor or a wizard.
  - `pass(W, to)` when a helped pass leaves, and `swap(you, old)` when control moves to another wizard.

If a mechanic needs something that isn't listed here, add it to the `FX.game` object or a new `FX.emit(...)` at the end of `void-wizard/scripts/game.js`, and add it to this list. With every feature off, the game must stay identical frame for frame: an `emit` with no listeners does nothing, and the multipliers are exactly 1.

## The Lab (Void Wizard)

The Lab is a feature (`features/lab.js`) that opens a toy box over the game and pauses it (the game reads `MOD.time` as 0 while it is open; Lab settings has Pause while open). Start, D-pad down or the LAB button opens it (Start or Circle closes it); a tap of Select changes the pixel filter, Select + left/right flips presets. The Lab takes Start and Select from the game (`LAB.skip('lab', [8, 9])`). Controller: up and down pick, left and right turn (hold R2 for five steps, L2 to jump to the end), L1 and R1 change shelf and holding either shows every shelf in a grid, Cross switches or plays, Square puts the knob back to normal, L3 pins it, R3 shrinks the panel to one slim bar, Triangle rolls the Dice, Select undoes, Start or Circle closes. The panel looks like the app (plates, black readouts, Saira, a ring around what's picked, the app's pixel icons loaded from `app/js/pixel.js`). **The panel does not show the shelf files as they are**: `LAYOUT` at the top of `features/lab.js` groups their knobs into shelves with headings (Game, Wizards, Solids, Demon, Rules, Colours, Camera, Distort, Colour grade, Film, Moments, PS1), by knob id. A new knob goes into `LAYOUT` where it belongs; one left out lands on a More shelf under its file's shelf name. Around them sit Pinned (first; knobs pinned on this phone, `localStorage` `ha.lab.pins`), Presets, On now (every knob that isn't normal), then Saved, Ideas and Lab settings. Saved's first row is the **start mix**: SET makes the game start with the knobs as they are (game.json `lab.start`, a phone edit), and Reset goes back to it. A saved mix is a **prototype**, kept in `game.json` under `lab.prototypes` (a phone edit, pushed like any setting). The Studio's Lab tab lists them (play, rename, note, copy, delete) and holds **ideas** (`lab.ideas`), each with an Ask Claude button.

**What the panel shows** is decided by `LAYOUT` in `features/lab.js`, not by the shelf files: knobs are grouped by what a player thinks about, in this order: Match, Map (with the Void's stars), Team, Wizards (moving, health, own solids, size, cloaks), Wizard stats (headings name each wizard by their own solid when Own solids is on), Throwing, Passing, Catching, Solid (flight, homing, resonance, extra solids), Solid look (colours, size, core, shell, edges, ground glow, light, fire aura, spiral), Abilities, Swords, Controls, Demon (with its look and colours), Rules, Camera (with the right stick), On screen (words, health bars, guides), Feel & time, Moments, Distort, Colour grade, Film, PS1, PS2, Sound. Shared lives; a wizard at zero health stays down (`W.labDown`, `downT` held up) until revived; L1 or V with a full-resonance dodecahedron is the Pentacle: next to a downed teammate it revives them for a life (a d12 roll of 12 is free; the captain, whoever's own solid is the dodecahedron, has the lives as health through `W.labMaxOverride`, which the Health shelf reads: a hit on the captain takes a life, a revive can't spend the last one, and the captain going down loses), anywhere else it arms the Solid, and an armed hit on a demon at its capture point captures it (sets its health below 0 inside `demonHit`, so the game takes it apart) and wins; otherwise `demonHit` keeps its health at 1; everyone down loses; the win and lose screens restart with X, Enter or a tap; it turns Health on), health (health bars, centipede touch damage, knockdown damage; it hooks the `camera` event to place the bars, so it stays after the camera shelf; `LAB.onScreen(x, y)` from look.js moves a point to where Curve, Bulge and Swirl draw it; a bar takes the colour of a recoloured cloak, `W.labCloak`). To add a toy, add it to the shelf it belongs on; for a new kind of toy, add a shelf file.
```js
LAB.shelf('time', 'Time', (game) => [
  { id: 'speed', label: 'Game speed', help: 'Below 1 is slow motion', min: 0.1, max: 3, step: 0.1, value: 1,
    apply: (v) => { game.MOD.time = v; } }
]);
```
- `value` is the normal value. At normal values a toy must change nothing.
- `setting: true` marks a toy that belongs to the Lab itself, not to a mix (it can still sit on a shelf in `LAYOUT`; a setting not placed there shows on Lab settings; a remembered setting's `apply` runs once the shelves are in) (Lab settings: Knobs per roll, Roll from, Pause while open, made in `features/lab.js`): saving, loading, Reset and the start mix leave it alone, and it is remembered on the phone in `localStorage` `ha.lab.settings`.
- **Presets** (the second shelf, `game.json` `lab.presets`, a phone edit like the others): whole mixes to flip between while playing, with D-pad left and right when the Lab is closed (the game doesn't use them) or `[` `]` on a keyboard. Each stands alone: loading one puts every other knob back to normal, not to the start mix. They are not prototypes and don't show in the Studio.
- `apply(v)` runs when the value changes; `frame(dt, v, now)` every frame and `camera(camera, lookAt, v, now)` after the camera is placed, both only while the value isn't normal (`now` is real seconds, so they work when time is frozen).
- `kind: 'onoff'` makes a switch. `dice: false` keeps a toy out of the Dice (switches stay out unless `dice: true`). `fmt(v)` shows the value its own way.
- `LAB.get('shelf.id')` reads another toy's value, so toys can work together (spawned solids follow World's solid gravity).
- `LAB.boost('shelf.id', value, seconds)` changes a knob for a while and then puts it back (the rules use it); `LAB.get` sees the boosted value, `LAB.base` the knob itself. The panel and saved prototypes keep the knob itself.
- `help` can be a function of the value, for knobs that pick from a list.
- Borrowed shaders: only ones whose licence allows it (MIT, CC0, BSD), with the author and licence kept next to the code. Godot and Shadertoy code needs turning into WebGL; three.js's own effects drop in (`lib/three-examples`).
- Post-processing materials need `depthTest: false`, or a picture drawn earlier can hide them.
- Patching game materials (dissolve, PS1): keep the material's earlier `onBeforeCompile` and call it first, add a word to `material.userData.labKey`, and set `customProgramCacheKey` to `'lab' + labKey`, so each mix of patches gets its own compiled program.
- A prototype stores only the values that aren't normal, by `shelf.id`, so renaming a toy's id loses it in saved prototypes. To move a toy to another shelf without losing it, give it its full old id (`id: 'look.trails'` on the Echo shelf).

**Ideas Claude has built**: remove them from `lab.ideas` in `game.json` and add their ids to `lab.done`. Her phone keeps its own copy of the list until she next changes it, so `lab.done` is what hides them in the Studio and in the game.

## Another game

Any game can have features:
- list `"engine/features"` first in its `load` list;
- set `FEATURES.game` to what features may touch;
- call `FEATURES.emit(...)` where things happen;
- give `studio.json` a `features` list (an empty list is fine).

## Lab presets travel by themselves

Presets are not in game.json any more: they live in `<game>/presets.json` (`{ presets: [...] }`). The Lab fetches the newest from GitHub when it opens (the contents API, with the token from Settings > GitHub if there is one; offline it uses the last list it saw, then the site's own copy), and every save, update or delete is sent straight up as its own commit to that file, applied to whatever is there at that moment, so two devices don't overwrite each other. Without a token the change waits on the device (`ha.lab.presetsPending.<game>`) and goes up the next time the Lab opens with one. Presets kept the old way (a phone edit of `lab.presets`) are folded into the file once and the edit is dropped.
