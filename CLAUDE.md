# Hedron (repo: home-arcade)

A no-code game-dev and arcade web app, used on an iPhone 16 Pro (home-screen app, Safari engine) with a GameSir controller. Site: https://pinchlemon.github.io/home-arcade/app/ . Games are played and tested with the controller; development happens by touch on the phone. It must work offline. Function comes before form, with lots of customization. Read `README.md` for what each tab does.

## How we work (the owner's rules)
- Changes go on a branch and are opened as a pull request with `gh api repos/pinchlemon/home-arcade/pulls -f title=... -f head=... -f base=main -F body=@/tmp/prN.md --jq .html_url` (`gh pr create` fails here). The owner merges PRs herself; never push to `main`.
- Commit messages and PR descriptions end with the attribution lines the session gives you.
- **Every change bumps the version in four places**, all to the same new number (`date +%s`): `CACHE` in `sw.js`, `BUILD` in the root `index.html` launcher, `version.json`, and `BUILD` in `app/js/build.js`. The launcher's BUILD must equal version.json or it reload-loops. Without the bump the phone keeps showing the old app.
- New files the app needs offline must be added to the `PRE` list in `sw.js`.
- The GitHub token lives only on the phone (Settings > GitHub, localStorage). Never put it in code.
- Test before opening a PR, and say honestly what was only tested in a browser and not on the phone/controller. Show screenshots of visual work when possible. Keep answers short and plain; she reads on a phone.
- When she names a preference (wording, spacing, colors), match it everywhere, not just in the one place she pointed at.
- Lab ideas (Void Wizard, `game.json` `lab.ideas`) that you finish: remove them from the list and add their ids to `lab.done`, without being asked (see `engine/features.md`).

## Shape of the code
- `app/`: the app. Vanilla ES modules, no build step. `app/js/main.js` is the shell (tabs, press feedback, layout fitting, update check); `screens/` has one file per tab plus `gameEditor.js` (Scene/Backdrop, Objects, Settings, undo/redo), `review.js` (changes before pushing), `sync.js` (push to GitHub, change dots); `games.js` (game list, edits stored on the phone as a list of changed settings, `localStorage` key `ha.game.<folder>`); `padnav.js` (controller ring for full-screen tools); `screens/spriteEditor.js` (the Art tab's sprite editor; `spriteSel.js` holds its selection and transform maths, `gif.js` its GIF export), `ase.js` (reads and writes .aseprite files), `artStore.js` (drawings kept on the phone in IndexedDB until pushed; `sw.js` serves them in place of the site's files); `screens/tileScene.js` and `screens/logicGraph.js` (the Scene and Logic tabs of games made with New game; `tileEditor.js` draws tiles); `input.js` (stick/D-pad/keyboard); `ui.js` + `pixel.js` (components and the pixel icon set).
- `engine/`: shared game engine (boot, actors, behaviors, symbols, `listen.html` plays a game's own sounds for the Sound tab; `tiles.js` is the runtime of games made with New game and `logic.js` runs their visual logic, whose boxes are listed in `logic.json`: add a box there and in `logic.js`).
- `crab-platformer/` is the model game: `game.json` (all numbers/objects/scenes), `studio.json` (what the Studio shows; its art and sound lists), `scripts/` (game code). Its look must never change by accident: the Waves mode was verified frame-for-frame identical after the split. - `void-wizard/` (3D, three.js) is editable for its numbers only: `scripts/game.js` is the game (moved out of `index.html` unchanged, then each tunable number reads `cfg('path', oldValue)` from `game.json`), loaded by `engine/boot.js`. Its `studio.json` has groups only and no `scene`, so the Studio shows just Settings (any game without `scene` works this way) and Art says it has no art yet. Verified frame-for-frame identical to the old page (seeded random, stepped frames, with and without keys held). It has **features**: add-ons in `void-wizard/features/<id>.js`, each with an on/off switch and its own settings in the Studio's Features tab. **Read `engine/features.md` before writing one**: it covers the three parts (code, numbers in `game.json` `features`, controls in `studio.json` `features`) and what the game hands over. The tab's Ask Claude button shares a request she pastes into a Claude Code session. Its **Lab** (a feature, `features/lab.js`) is a toy box over the running game: knobs on shelves (`void-wizard/lab/<shelf>.js`), Dice, and saved prototypes and ideas in the Studio's Lab tab; `engine/features.md` covers adding toys. With every feature off, the game must stay frame-for-frame identical.
- Phosphor and Purgatory Bowl are plain code games, not yet editable.
- Update flow: the app compares its own `BUILD` with `version.json` on GitHub; idle it reloads itself, inside a full-screen tool it waits until you leave. Settings > Display shows the build time; Update clears saved copies.

## Design system
- Dark plates; round black "wells" with white pixel icons; Saira font; slightly rounded corners (`--r-*` variables in `app/app.css`).
- One color per section: Arcade #ff5a1f (dodecahedron), Studio #7dff6a (cube), Art #ff4fd8 (icosahedron), Sound #4d7cff (octahedron), Settings #ffd23f (tetrahedron).
- Selection uses a ring; pressing a button highlights it like a selected one and only one thing is lit at a time; one soft click sound per press. The page never scrolls; layouts are fit to the screen (rows per page 1 to 4). Landscape has its own layout (tab column left, panel narrow with the shape on top).
- iOS quirks to remember: home-screen apps get less height than the screen (black band), so layout is centered by measurement; iOS Safari hides a controller from a page until a button is pressed (the app tells launched games via `sessionStorage` `ha.pad`); Low Power Mode caps pages at 30 fps.

## Testing
The owner's app customizations (redrawn icons, button text, order) live in `app/custom.json` once she pushes them; a fresh test browser loads them, so screenshots match her phone.
Serve locally with `python3 -m http.server 8765` from the repo root and drive it with Playwright (at 402x874 for portrait, 874x402 or 859x329-395 with side margins for landscape). Fake a controller with an init script that replaces `navigator.getGamepads`. The old test scripts were kept outside the repo and are not available in a fresh session; rewrite what you need.
